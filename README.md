## Правила ведения репозитория

**Один коммит = одно логическое изменение.** Например: один раздел документа, одно уточнение требований или одна правка по замечанию ревьюера. Нельзя копить правки за вечер и отправлять их одним коммитом.

**Сообщение описывает, зачем сделано изменение**, а не «что потыкали в файле».

**Формат:** `тип: краткое описание на русском`. Язык сообщений во всём репозитории русский.

| Тип | Когда использовать |
|-----|--------------------|
| `feat` | добавлено новое содержание (требования, раздел, сценарий) |
| `docs` | уточнение, правка формулировок, оформление, README |
| `refactor` | перестройка структуры документа без изменения смысла |
| `chore` | служебное: `.gitignore`, структура папок, экспорт |

**Допустимые сообщения:**

```text
feat: добавлены требования к импорту расписания из внешних систем
docs: уточнены нефункциональные требования к доступности
refactor: реструктуризация раздела «Границы кейса»
docs: учтено замечание ревью по критериям приёмки
```

**Недопустимые сообщения:**

```text
update
fix
правки
asdf
готово
```

## Ветки и ревью

1. `main` содержит только согласованные версии. Напрямую в `main` не коммитим.
2. Каждая задача делается в отдельной ветке от актуального `main`: `feature/<что-делаем>` или `student/<кто-делает>`.
3. Готовую ветку выкладываем на GitHub и открываем Pull Request в `main`.
4. Другой участник команды проводит ревью: оставляет замечания в Pull Request.
5. Автор исправляет замечания. Принятые и отклонённые (с обоснованием) замечания фиксируются в `review_logs`.
6. Журналы ревью заливаются в ветку `reviews`
7. После одобрения ветка сливается в `main`.
