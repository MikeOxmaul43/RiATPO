| НФТ-19 | удобство использования | Пользователь должен находить занятия дня за малое число действий | MAX: ≤ 2 нажатия от входа в «Расписание занятий» до занятий дня; веб: ≤ 3 действия | счёт на тестовом сценарии с привязанным аккаунтом | ФТ-5.1, ФТ-5.2 |

## 2. Группы из названия работы

| Группа | Где закрыта | Основание |
|--------|-------------|-----------|
| Аутентификация | НФТ-10, НФТ-11 | Сотрудники входят существующей корпоративной учётной записью университета. Пользователи MAX подтверждают аккаунт через Moodle (ФТ-5.4). Отдельный пароль расписания не заводим |
| Авторизация | НФТ-10, НФТ-12 | Диспетчер формирует, меняет и публикует расписание; сотрудник учебного управления смотрит журнал и отчёты; студент и преподаватель видят только опубликованную версию |
| Структуры хранения | НФТ-9, НФТ-13, НФТ-14 | Шесть групп данных из лабораторной 3: версия, занятие, журнал, уведомление, сопоставление аккаунта MAX, загрузка семестра. Справочники не хранятся и не меняются |
| Политики защиты | НФТ-15, НФТ-16 | Состав пакета для MAX и канал передачи, а не «данные под замком» без списка |
| Развёртывание | НФТ-17 | Система ставится на сервер университета; зависимости запуска перечислены в условиях НФТ-17 |
| Эксплуатация | НФТ-9, НФТ-18 | Сбой публикации или смежной системы заметен дежурному, а не пользователю |
| Протоколы | НФТ-16 | HTTPS REST со смежными системами; формат MAX согласуется (UR, п. 5.8) |
| Потоки данных | НФТ-5, НФТ-8 | Корпоративные системы → система → MAX; MAX → система; система ↔ Moodle. Исходник `landscape.puml`, последовательности — в разделе 8 |
| Балансировка нагрузки | вне рамок | Концепция (раздел 6) не требует нескольких экземпляров службы. Первый выпуск работает в одном экземпляре, нагрузку ограничивает НФТ-1 |

## 5. Приёмка

### НФТ-1

```text
Given: опубликована версия семестра, к расписанию одновременно обращаются 500 пользователей
When: пользователь открывает расписание дня в MAX или в веб-версии
Then: расписание показано, время ответа ≤ 2 с (95-й процентиль)
```

### НФТ-2

```text
Given: данные семестра загружены, нагрузка полная, слоты сконфигурированы
When: диспетчер запускает автосоставление на семестр
Then: сводка результатов показана за время ≤ 15 мин
```

### НФТ-3

```text
Given: изменение опубликовано, у 500 получателей есть привязанный аккаунт MAX
When: система отправляет уведомления
Then: ≥ 95% уведомлений принято MAX за ≤ 5 мин после публикации изменения
```

### НФТ-4

```text
Given: замерено базовое время подготовки расписания семестра
When: диспетчер готовит расписание в приложении от загрузки до утверждения
Then: время подготовки ≤ 50% базового значения
```

### НФТ-5

```text
Given: версия утверждена, MAX отказывает в части попыток
When: система публикует версию
Then: расхождений версий между MAX и веб-версией = 0
```

### НФТ-6

```text
Given: в версии есть занятие со статусом «с конфликтом»
When: диспетчер запрашивает утверждение и публикацию
Then: опубликованных версий с конфликтом = 0, диспетчер видит перечень конфликтов
```

### НФТ-7

```text
Given: одна из корпоративных систем недоступна
When: диспетчер запускает загрузку и автосоставление
Then: занятий, размещённых по данным недоступной системы = 0
```

### НФТ-8

```text
Given: первая отправка не удалась, диспетчер повторяет её дважды
When: система передаёт данные в MAX
Then: дублей занятий после 2 повторов = 0, повторных уведомлений одному получателю об одном изменении = 0
```

### НФТ-9

```text
Given: создана ежесуточная копия, на стенде имитируется сбой хранилища
When: администратор восстанавливает данные из копии
Then: потеря данных ≤ 24 ч, восстановление ≤ 4 ч
```

### НФТ-10

```text
Given: пользователь без сессии или без роли диспетчера вызывает функцию редактирования
When: система обрабатывает запрос
Then: запрос без сессии отклонён с кодом 401, без нужной роли с кодом 403, отклонено 100%; сессия истекает через ≤ 30 мин бездействия
```

### НФТ-11

```text
Given: аккаунт MAX не привязан к аккаунту Moodle
When: пользователь запрашивает личное расписание
Then: личное расписание не показано, ответов с чужим расписанием = 0, паролей Moodle в хранилище = 0
```

### НФТ-12

```text
Given: есть версия «утверждена» и опубликованная версия
When: студент открывает расписание
Then: занятий неопубликованных версий в ответе = 0
```

### НФТ-13

```text
Given: выполнены загрузка данных, автосоставление и ручная правка
When: проверяются вызовы к корпоративным системам и схема хранилища
Then: операций записи в корпоративные системы = 0, таблиц-копий справочников = 0
```

### НФТ-14

```text
Given: в журнале есть запись о правке опубликованного занятия
When: пользователь пытается изменить или удалить запись
Then: записей, изменённых или удалённых после создания = 0, срок хранения ≥ 3 лет
```

### НФТ-15

```text
Given: версия опубликована, изменение отправлено
When: проверяется состав пакетов, переданных в MAX
Then: в пакете ≤ 8 полей расписания, персональных данных студентов = 0
```

### НФТ-16

```text
Given: смежная система не отвечает, соединения установлены по сети
When: система выполняет вызов
Then: соединений по TLS 1.2 или выше 100%, через ≤ 10 с вызов считается отказом, ответов «успех» без ответа = 0
```

### НФТ-17

```text
Given: есть чистый сервер и инструкция развёртывания
When: администратор разворачивает систему
Then: система прошла проверку состояния за ≤ 30 мин
```

### НФТ-18

```text
Given: система запущена, проверка состояния идёт раз в 1 мин
When: проверка состояния даёт сбой
Then: дежурный получил оповещение за ≤ 5 мин после первого сбоя
```

### НФТ-19

```text

Then: в MAX ≤ 2 нажатия, в веб-версии ≤ 3 действия до занятий дня
```

### КНТ-1. Прочитать справочники и нагрузку семестра

**Требование.** Система «Расписание» должна получить из 1С:Университет ПРОФ преподавателей, учебные группы, аудитории и нагрузку выбранного семестра и ничего в 1С не менять. Если часть операций не выполнена, система называет, чего не хватает, и не подставляет устаревшие данные.

| Поле | Содержание |
|------|------------|
| Поставщик | 1С:Университет ПРОФ, публикации HTTP-сервисов `hs` |
| Потребитель | Система «Расписание», загрузка семестра |
| Протокол | REST, HTTP/1.1, JSON. Все операции — `GET`, тела запроса нет |
| Операции | пять `GET`, таблица ниже |
| Связанные требования | ФТ-1.1, НФТ-7, НФТ-13, НФТ-16 |
| Предусловие | Диспетчер вошёл под корпоративной учётной записью и выбрал семестр. Адрес базы и учётная запись чтения заданы в настройках интеграции |
| Постусловие успеха | Группы данных «Преподаватель», «Учебная группа», «Аудитория», «Нагрузка по дисциплине» получены, результат загрузки зафиксирован со статусом «полная» |
| Постусловие отказа | Загрузка «частичная», недоступные операции названы, по их данным занятия не размещаются |

Адреса и учётная запись читаются из настроек интеграции. Пароль в документ не входит.

| Операция | Путь после базового адреса | Что отдаёт | Группа данных ФТ | Таймаут по умолчанию |
|----------|----------------------------|------------|------------------|----------------------|
| Структура университета | `/hs/volgmed_data/Department_University` | дерево подразделений: факультеты, кафедры, корпуса, аудитории | «Аудитория» | 1800 с |
| Сотрудники | `/hs/volgmed_data/employees_v1` | сотрудники с должностью и подразделением | «Преподаватель» | 1800 с |
| Учебные группы | `/hs/Shedule/study_groups` | список названий групп | «Учебная группа» | 600 с |

| Нагрузка плана | `/hs/Shedule/disciplines_departments?number={planNumber}` | строки нагрузки одного плана | «Нагрузка по дисциплине» | 120 с на один план |

#### Запрос

Общие правила для всех пяти операций.

| Поле | Место | Тип | Обязательность | Смысл | Правило |
|------|-------|-----|----------------|-------|---------|
| `Authorization` | заголовок | `Basic <base64(логин:пароль)>` | да | право чтения публикации 1С | Учётная запись только для чтения. Пароль не пишется в журнал и не хранится в коде |
| `Accept` | заголовок | `application/json, text/plain, */*` | да | система ждёт JSON | Иное тело как данные не разбирается |
| `number` | query, только «Нагрузка плана» | строка | да | `plan_number` из «Учебных планов» | Один вызов на один номер плана. Номер не вводит пользователь |

```http
GET /university_volgmu/hs/Shedule/disciplines_departments?number=000004748 HTTP/1.1
Authorization: Basic <логин:пароль в base64>
Accept: application/json, text/plain, */*
```

#### Ответ

Годный ответ — HTTP 2xx, непустое тело, JSON-объект или массив и нет `"error": true`. Перед первым `{` или `[` в теле может стоять произвольный префикс: система отрезает его и разбирает остаток.

Оболочка отказа, где она есть:

```json
{ "error": true, "message": "строка", "error_text": "строка" }
```

Достаточно одного из полей `message` или `error_text`. При `"error": true` содержимое не разбирается.

Поля, которые система читает. Остальные игнорируются.

| Операция | Поле | Тип | Правило |
|----------|------|-----|---------|
| Структура университета | `GUID`, `Представление`, `ВидСтруктуры`, `Подчиненные[]` | строки, рекурсивный массив | Аудитории — узлы с `ВидСтруктуры` = «Аудитории». Дерево обходится вниз по `Подчиненные` |
| Структура университета | `Характеристики[]` | массив объектов «ключ — значение», сливаются в одну карту | Читаются `Количество посадочных мест` или `Количество мест`, `Тип помещения`, `Наименование комнаты`, `Адрес` |
| Сотрудники | `ФИО`, `Работа[].Должность`, `Работа[].Подразделение`, `Работа[].Преподаватель` | строки, справочные ссылки | Преподаватель — запись, у которой в `Работа[]` признак `Преподаватель` истинен. Значения `да`, `true`, `1`, `истина` без учёта регистра |
| Сотрудники | `Статус` | строка | Читается для отбора действующих |
| Учебные группы | `groups[]` | строки или объекты `{ "name": … }` | Нет массива — список пуст. Поле есть, но не массив — ошибка разбора |
| Учебные планы | `plan_number` | строка | Без номера строка не берётся. Повторы сводятся к последней записи |
| Учебные планы | `speciality`, `academic_year`, `study_form`, `faculty`, `is_posted` | строки, `is_posted` логическое | `is_posted` отсутствует или не `false` — считается истиной |
| Нагрузка плана | `discipline`, `load`, `quantity`, `unit`, `semester_number`, `subdivision` | строки и числа | Строка без `discipline` или без `load` пропускается |

Остальные поля `employees_v1` (дата рождения, телефон, почта, идентификаторы научных профилей, соцсети) система не читает и не сохраняет.

```json
{
  "error": false,
  "number": "000004748",
  "data": [
    {
      "semester_number": 1,
      "discipline": "Анатомия",
      "load": "Лекционные занятия",
      "quantity": 6,
      "unit": "Часы",
      "subdivision": "Кафедра анатомии"
    }
  ]
}
```

Система в 1С ничего не пишет: у неё нет вызовов `POST`, `PUT`, `PATCH` и `DELETE` к 1С.

#### Исходы

| Исход | Как выглядит | Что это значит | Что делает система |
|-------|----------------|----------------|--------------------|
| Данные получены | HTTP 2xx, `error` не `true`, массив или объект разобран | Операция выполнена | Данные идут в загрузку семестра |
| Отказ 1С | HTTP 2xx и `"error": true`, либо код вне 2xx, в теле начало текста ошибки | 1С ответила отказом | Операция считается недоступной, её группа данных не используется, загрузка «частичная» |
| Ответа нет | таймаут, обрыв, пустое тело, тело не разобралось, поле данных не массив | Годных данных нет | То же, что отказ. Устаревшие данные прошлой загрузки не подставляются |
| Нагрузка одного плана недоступна | отказ или таймаут на одном `number` при успехе остальных | Нет нагрузки по этому плану | Планы без нагрузки названы в результате загрузки, по ним занятия не размещаются. Остальные планы работают |

Таймауты в таблице операций — значения по умолчанию из настроек интеграции, их можно менять. Они длиннее порога в НФТ-16, потому что операции «Структура университета» и «Сотрудники» отдают весь список разом.

#### Приёмка

```text
Given: диспетчер выбрал семестр, 1С отвечает на все пять операций
When: система запускает загрузку
Then: группы данных «Преподаватель», «Учебная группа», «Аудитория» и «Нагрузка по дисциплине» получены, загрузка «полная», в 1С не отправлено ни одного запроса кроме GET
```

```text
Given: операция «Учебные группы» возвращает код вне 2xx, остальные операции отвечают
When: система запускает загрузку
Then: загрузка «частичная», «Учебные группы» названа недоступной, занятий, размещённых по данным групп, нет
```

```text
Given: ответ 1С содержит "error": true
When: система разбирает ответ
Then: операция считается недоступной, данные прошлой загрузки не подставлены
```

```text
Given: у 1С отказ на одном номере плана из десяти
When: система запрашивает нагрузку планов
Then: девять планов загружены, десятый назван в результате загрузки без нагрузки
```

| Поле | Место | Тип | Обязательность | Смысл | Правило |

| Токен коннектора | заголовок авторизации | строка | да | право подключённого университета передавать данные | Выдаётся MAX по запросу на digital.vuz@max.ru. В репозиторий и журнал не попадает |

#### Ответ

#### Исходы

Срок ожидания одного вызова — по НФТ-16, 10 секунд. Размер порции подбирается так, чтобы вызов в него укладывался.

| Исход | Как выглядит | Что это значит | Что делает система |
|-------|----------------|----------------|--------------------|
| Пакет принят | HTTP 2xx на все вызовы | MAX принял справочники и события | Версия «Опубликована», прежняя «Заменена», веб-версия обновляется |
| Часть вызовов отклонена | HTTP вне 2xx хотя бы на одном вызове | MAX принял не всё | Публикации нет ни в одном канале, версия «Утверждена». Повтор отправляет пакет заново |
| MAX недоступен | обрыв, таймаут, нет ответа | Принятого нет | То же. Сообщение об ошибке диспетчеру, повтор по его команде |
| Токен не принят | HTTP 401 или 403 | Нет права передавать данные | Публикации нет. Дежурный узнаёт об этом по НФТ-18 |

Повтор той же отправки не должен создавать дубли занятий (НФТ-8). Методы MAX названы «добавление или обновление»; ключ записи, по которому MAX узнаёт повтор.

#### Приёмка

```text
Given: версия утверждена, токен коннектора действителен, MAX доступен
When: система публикует версию
Then: все вызовы пакета вернули 2xx, версия «Опубликована», прежняя «Заменена», в пакете событий не больше 8 полей
```

```text
Given: MAX отклоняет вызов events
When: система публикует версию
Then: версия остаётся «Утверждена», прежняя опубликованная действует, диспетчер видит ошибку
```

```text
Given: первая отправка не удалась, диспетчер повторяет её дважды
When: система передаёт пакет в MAX
Then: в MAX нет дублей занятий
```
Последовательность: [`diagrams/sequence-max-publish.puml`](diagrams/sequence-journal.puml).

### КНТ-3. Отправить уведомление об изменении

**Требование.** После публикации разового изменения система должна передать в MAX текст «было / стало» адресатам и сохранить результат отправки по каждому получателю. Недоставленное остаётся в списке сбоев и уходит повторно, не создавая повторных уведомлений.

| Поле | Содержание |
|------|------------|
| Поставщик | MAX |
| Потребитель | Система «Расписание», уведомления |
| Протокол | REST, HTTPS, JSON (НФТ-16) |
| Операция | `⟨уточнить⟩`: в методах Open API, показанных на странице подключения, есть только группа `import` |
| Связанные требования | ФТ-7.1, ФТ-7.2, ФТ-7.3, НФТ-3, НФТ-8, НФТ-16 |
| Предусловие | Изменение опубликовано по КНТ-2, получатели определены (ФТ-7.1), их аккаунты MAX сопоставлены |
| Постусловие успеха | MAX принял сообщения, записи уведомлений со статусом «отправлено» |
| Постусловие отказа | Записи со статусом «ошибка отправки», диспетчер видит список и может повторить |

Содержание сообщения: дисциплина, значения «было» и «стало». Персональных данных студентов в тексте нет (НФТ-15).

| Исход | Как выглядит | Что делает система |
|-------|----------------|--------------------|
| Принято | успех по получателю | Запись «отправлено» |
| Отказ или нет ответа | код вне 2xx, таймаут, обрыв | Запись «ошибка отправки», получатель в списке сбоев ФТ-7.3 |
| Повтор | диспетчер повторяет отправку | Адресат получает одно уведомление об одном изменении |

```text
Given: изменение опубликовано, у 500 получателей есть привязанный аккаунт MAX
When: система отправляет уведомления
Then: не меньше 95% принято MAX за 5 минут, у каждого получателя одно уведомление об этом изменении
```

Последовательность: [`diagrams/sequence-max-notify.puml`](diagrams/sequence-journal.puml).
